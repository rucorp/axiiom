# Security Policy

## Supported Scope

This security policy applies to the **source code of the axiiom.ru website**
hosted in this repository (ООО «Аксиома» / AXIIOM). It covers:

* The static site build pipeline (`build.py`, `test_site.py`).
* The site's HTML, CSS, and JavaScript sources (`*.src.js`, `*.src.css`,
  `nav.js`, `styles.css`, page templates).
* Configuration and deployment files in this repository.

Out of scope: third-party services, infrastructure not managed in this repo,
and the content of linked external systems.

## Reporting a Vulnerability

If you discover a security vulnerability, please report it **privately**. Do not
open a public GitHub issue or discuss it publicly, as that may put users at
risk.

**Report to:** **hello@axiiom.ru**

Please include:

* A clear description of the vulnerability and its impact.
* The affected page, URL, or file in this repository.
* Steps to reproduce (where applicable).
* Any relevant logs, screenshots, or proof of concept.

> **Do not publish a public proof of concept** until the issue is resolved and
> coordinated disclosure is agreed upon.

## Response Window

We aim to acknowledge and triage every private report according to the
following targets:

| Stage | Target |
|-------|--------|
| Acknowledgement of receipt | within **72 hours** |
| Initial assessment / severity classification | within **7 days** |
| Remediation of high-severity issues | within **30 days** |
| Remediation of lower-severity issues | best effort, scheduled with reporter |

If you do not receive an acknowledgement within 72 hours, please send a follow-up
email to **hello@axiiom.ru**.

## Severity & Disclosure

* We will keep you informed of progress on a fix.
* Once a fix is released, we are happy to credit the reporter (unless anonymity
  is requested).
* Coordinated disclosure is preferred; public disclosure before a fix is
  available is discouraged.
