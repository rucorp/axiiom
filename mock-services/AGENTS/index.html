AGENTS.md — правила работы ИИ-агентов с mock-services ​

Инструкция для агентов (Arena Agent Mode, Claude Code и др.), которые меняют этот репозиторий. Всё, что заявлено ниже, проверено по файлам репозитория (package.json, CONTRIBUTING.md, scripts/*, .github/workflows/ci.yml); додумывать нельзя — только сверяться с первыми руками.

Полные правила для людей — CONTRIBUTING.md. Планирование доработок и статусы задач — «план доработок» (бриф — во внутреннем репозитории mock-services-docs). Подготовка к глубокому аудиту и карта покрытия — пакет подготовки к аудиту (в mock-services-docs).

0. Правило конфликтов ​

Если инструкция в чате противоречит этому файлу или CONTRIBUTING.md — приоритет у файлов репозитория, а расхождение агент обязан записать в описание PR, а не «разрешить сам». Не угадывайте там, где документация противоречива: ставьте [VERIFY]/вопрос.

1. Что нельзя ломать ​

  1. Zero dependencies. В package.json нет dependencies и devDependencies. Любая новая зависимость — стоп и вопрос владельцу.
  2. Протокольное поведение адаптеров (форматы полей, коды ошибок, подписи, статусы) — не менять, если задача этого прямо не требует. Эталон: protocols/*.json + конспекты провайдеров в приватном репозитории mock-services-docs.
  3. Обратная совместимость self-hosted: поведение без MOCK_HOSTED/токенов не меняется; default-песочница и её креды — тоже.
  4. Никаких реальных секретов, PAN и ПДн в коде, тестах, логах, примерах и fixtures.
  5. Историю git и теги не переписывать, main не пушить напрямую.

4. Формальные требования к файлам ​

  1. SPDX в каждом исходнике. Первая строка — // © 2026 ООО «Аксиома» ИНН:7842223709 · mock-services · Apache-2.0, вторая — // SPDX-License-Identifier: Apache-2.0, затем 'use strict';. Сейчас 17/17 .js соответствуют; новый файл без шапки — дефект.
  2. Markdown-доки в docs/** и корневые публичные доки начинаются со стандартной шапки проекта: © 2026 ООО «Аксиома» ИНН:7842223709 · mock-services · Apache-2.0 + строка SPDX-License-Identifier: Apache-2.0. Правоустанавливающая формулировка про «все права» (all-rights-reserved) не используется — проект под Apache-2.0 (решение владельца 15.10, MS-05); проверка — npm run check:copyright. Агент не «исправляет» шапки по своей инициативе и не добавляет правоустанавливающую строку в новые служебные файлы, не требуемые стандартом (пример — CONTRIBUTING.md, AGENTS.md).
  3. Ссылки — только относительные между доками (их проверяет check:links). Учитывайте область проверки: README.md, CONTRIBUTING.md, SECURITY.md, docs/**, services/**, packages/** (scripts/check-docs-links.js:23,54-58) — CHANGELOG.md и новые корневые файлы проверяются вручную.
  4. Стиль: CommonJS, 2 пробела, одинарные кавычки, комментарии по делу на русском с английскими терминами. Никакого «мусора» из других языков и случайных символов.
  5. Ссылка на источник истины в каждом спорном месте: конспект провайдера в приватном mock-services-docs (раздел <provider>/…) с датой сверки; внутренний вывод помечать явным [FORK]/«документированный форк».

5. Env-переменные: правило пяти мест ​

Любое изменение/добавление MOCK_* обязано отразиться в: docker-compose.yml → docker-compose.include.yml → services/<name>-mock/README.md (env-таблица) → SECURITY.md (если влияет на модель угроз) → CHANGELOG.md. Исключений нет. Правило проверяется скриптом npm run check:env (scripts/check-env-parity.js): он сверяет server.js с README сервиса, тремя compose-файлами и SECURITY.md, а также дефолты MOCK_PORT и ${VAR:-…}. Незакрытый долг ведётся явно в KNOWN_INCLUDE_DEBT (переменные, которые адаптеры читают, но которые в include не проброшены, — менять include-набор без решения владельца нельзя, §7) и печатается в выводе проверки; новый дрейф валит CI.

6. Process: ветка, коммит, PR ​

  1. Ветка: arena/<срез>-<тема> (или fix/…, docs/…) → PR в main. В main не пушить.
  2. Один PR = одна логически связанная группа задач (волны PR-A…PR-G заданы в брифе, §9).
  3. В описании PR обязательна строка Closes #<номер issue> — без неё задача не считается принятой (именно так закрываются #8, #12, #15, #22, #33, #37, #43).
  4. Отчёт в описании PR — по схеме: что сделано / что НЕ сделано / развилки и вопросы владельцу / риски и что осталось непроверенным / команды прогонов с их выводом.
  5. Ссылки на конспекты провайдеров (приватный mock-services-docs) и коды ошибок — с указанием раздела доки.
  6. Если задача [DECISION] — PR готовит варианты, а не решение владельца.
  7. Docs-only правки не трогают поведение сервисов; npm test прогоняется в любом случае.

7. Чего агент делать не должен ​

  • Реализовывать задачи из «будущих волн» без постановки (в том числе MS-правки из брифа).
  • Менять docker-compose.include.yml так, чтобы потребители получили другой набор env (это deployment artifact; пин образа — только через MOCK_IMAGE_DIGEST, см. «Обновление базового образа» в CONTRIBUTING.md).
  • Отключать/ослаблять тесты, чтобы CI стал зелёным; менять check:drift под новую реализацию.
  • Добавлять .html-копии документации провайдеров (юридический риск, см. аудит-преп §2.7).
  • Публиковать образы/релизы, менять настройки репозитория, GHCR-пакет, protected branches.
  • Писать «проверено / закрыто» без файл:строка и без вывода команды.

8. Специфичные для проекта ловушки (проверено на коде) ​

  • MOCK_* разбираются через flagEnabled (boolean) и parseDuration/parseMsOr (числа: пустая строка → fallback, 0 разрешён). Ручной parseInt(x, 10) || N ломает «выключить нулём» — см. комментарий в services/atol-mock/server.js:109-118.
  • check:drift сверяет наличие строки в server.js подстрокой: маршрут, упомянутый только в комментарии, будет засчитан как реализованный.
  • readBody на превышении лимита отвечает 413 и намеренно дренирует остаток тела — не «закрывать соединение» без задачи.
  • Управляющие токены принимаются из query только в non-hosted (MS-06 + хвосты #121/Ф-1…Ф-3): ответ со ссылками на консоль переносит принятый токен в HttpOnly-cookie (core.sessionCookiesFromQuery), Location и HTML токенов не содержат, а в hosted ?admin_token=/?operator_token=/?sandbox_token= отклоняются (services/kassa-mock/selftest.js, блок #5 A-20 + Ф-1/Ф-3; packages/core/selftest.js, блок #121).
  • escapeHtml (", ') обязателен и в атрибутах; HTML собирается конкатенацией — никакой вставки значений интегратора «как есть».
  • Состояние per-sandbox: state — Proxy поверх контекста запроса; новый код, читающий state вне sandboxRuntime.run(...), попадает в default/активную песочницу.
  • Время доменных сущностей — только через clock.now(); учтите, что createSandboxRuntime сейчас живёт на wall-clock (аудит-преп §2.4).

10. Документы вне публичного репозитория ​

Часть проектной документации живёт в закрытом репозитории mock-services-docs: внутренняя спека, бриф доработок, аудиты и чек-листы. Ссылки на такие документы оформляются сноской (имя документа без ссылки) — публичная часть репозитория самодостаточна, а сноска объясняет, откуда взят контекст.
