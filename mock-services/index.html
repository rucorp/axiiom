mock-services — тестовые моки банков и касс по официальным протоколам ​

Открытый сервис, который имитирует банк-эквайринг и облачную кассу/ОФД по их официальным протоколам, чтобы магазин, платформа или интегратор тестировал платёжную и фискальную интеграцию до договора с провайдером — с честными схемами, кодами ошибок, сценариями отказов и подсказками «что не так в запросе».

Статус: alpha (0.7.0). См. дорожную карту. Каждый адаптер следует клиентскому контракту провайдера, но одной смены URL для перехода в production недостаточно — проверьте конфигурацию и безопасность.

Поддерживается 10 адаптеров:

  • Банки: Т-Банк EACQ (Мультирасчеты Wave 2, СБП QR, рекурренты, чарджбэки) :3100, ЮKassa REST /v3 :3102, АТОЛ Онлайн v4 :3103, Альфа-Банк REST :3104, Сбер Ecom REST v1.1.11.1 :3105, ВТБ SMB E-commerce :3106
  • Кассы/ОФД: OFD Ferma 54-ФЗ :3101, Первый ОФД OKassa :3107, Контур.ОФД read/reconciliation :3108, Такском API v2 read-only :3109
  • Общее: мульти-песочницы (X-Mock-Sandbox), экзаменатор вебхуков (/mock/verify-merchant), OpenAPI 3.1 (/openapi.json), детектор дрейфа (npm run check:drift), виртуальные часы (/mock/time)

Для read-only ОФД: Контур.ОФД — гайд и README сервиса; Такском — гайд и README сервиса.

Зачем ​

  1. Тестовые контуры банков/ОФД доступны только после договора — мок даёт протокол сразу.
  2. Реальные шлюзы возвращают сухие коды — мок объясняет ошибку, поле и ссылку на доку.
  3. Сценарии отказов (недостаток средств, таймаут, дубль вебхука, чарджбэк, отказ ККТ) — переключателем.
  4. Новые провайдеры добавляются адаптером-декларацией, без форка сервиса.
  5. Журнал (/admin/journal) показывает, как мок понял запрос и что ответил.

Быстрый старт ​

bash
# 1. Все 10 сервисов целиком
docker compose up            # :3100 tbank, :3101 kassa, :3102 yookassa, :3103 atol, :3104 alfa, :3105 sber, :3106 vtb, :3107 first-ofd, :3108 kontur-ofd, :3109 taxcom
# Харденинг (MS-04): read-only rootfs, tmpfs /tmp, cap_drop ALL, no-new-privileges, pids_limit 256, init

# Порты по умолчанию слушают 127.0.0.1. Для сети:
MOCK_TBANK_BIND_IP=0.0.0.0 docker compose up
# Не используйте 0.0.0.0 публично без operator/admin токенов и TLS.

# 2. Без Docker (Node >= 18, зависимостей нет)
npm run start:tbank          # :3100
npm run start:kassa          # :3101
npm run start:yookassa       # :3102
npm run start:atol           # :3103
npm run start:alfa           # :3104
npm run start:sber           # :3105
npm run start:vtb            # :3106
npm run start:first-ofd      # :3107
npm run start:kontur-ofd     # :3108
npm run start:taxcom         # :3109

# 3. Проверить
npm test

Стенд одной командой (без клонирования) ​

docker-compose.staging.yml — tbank-mock :3100 /health + kassa-mock :3101 /healthz из GHCR-образа с digest:

bash
curl -fsSLO https://raw.githubusercontent.com/rucorp/mock-services/main/docker-compose.staging.yml
docker compose -f docker-compose.staging.yml up -d

URL: http://<хост>:3100/v2 и http://<хост>:3101/possystem/v1. Публичные URL страниц — MOCK_TBANK_PUBLIC_BASE_URL/MOCK_KASSA_PUBLIC_BASE_URL. Для общего хоста задайте MOCK_OPERATOR_TOKEN/MOCK_ADMIN_TOKEN и TLS — см. SECURITY.md.

Что уже умеет мок ​

Кратко: все адаптеры поддерживают протоколы провайдеров, подписи/авторизацию, вебхуки с ретраями, машины состояний, негативные сценарии (X-Mock-Scenario), виртуальные часы (/mock/time), песочницы RFC-001 и журнал с curl.

Полная матрица — в docs/capabilities.md (по 10 сервисам, без огромных строк в README).

Дорожная карта ​

Этапы 0–17: от ядра и DX до 10 внешних адаптеров (ЮKassa, АТОЛ, Альфа, Сбер, ВТБ, Первый ОФД, Контур.ОФД, Такском) + мульти-песочницы, часы, OpenAPI, drift-детектор.

Подробно — в docs/roadmap.md и CHANGELOG.md.

Контейнерный харденинг ​

init, read_only, tmpfs /tmp, cap_drop ALL, no-new-privileges, pids_limit 256, graceful shutdown с синхронным сбросом состояния (150 мс debounce) и exit 0 ≤ 2 с.

Подробно — в docs/hardening.md и SECURITY.md.

Безопасность ​

Тестовый стенд: все креды фейковые, платежи по тестовым картам. /admin без аутентификации по умолчанию (локальный DX) — см. SECURITY.md. Для публичного размещения: MOCK_HOSTED=1, MOCK_OPERATOR_TOKEN, MOCK_ADMIN_TOKEN, MOCK_SANDBOX_TOKEN (без него default-песочница отвечает 404), TLS и egress-фильтр. Токены не возвращаются в URL/HTML — после POST /admin/login HttpOnly-cookie. Песочницы изолированы по RFC-001.

Участие ​

Issues и PR приветствуются: CONTRIBUTING.md. Полезнее всего: расхождения с официальной докой (со ссылкой), новые сценарии отказов, новые адаптеры. Правила для ИИ-агентов — AGENTS.md.

Ограничения и лимиты ​

Общий бюджет состояния песочниц (PD-02): MOCK_SANDBOX_MAX_STATE_BYTES (per-sandbox, дефолт 8 МиБ при квоте документов) и MOCK_SANDBOX_GLOBAL_MAX_STATE_BYTES (все песочницы, дефолт 64 МиБ). 0 выключает лимит. Превышение → 400 + sandbox_state_budget_exceeded. См. ядро и env-таблицы сервисов.
