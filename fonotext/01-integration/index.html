01. Интеграция и анкета подключения

Версия 1.0 от 2026-10-03. Что нужно для подключения Fonotext к телефонии заказчика, какие возможности включаются после интеграции, и анкета для старта.

1. Как происходит подключение

  1. Заказчик заполняет анкету (раздел 4) — 20 минут.
  2. Мы подключаемся к системе записи (типы доступа — раздел 2) и получаем тестовую выборку.
  3. Пилот 2–4 недели: качество, таксономия, дашборды — на записях заказчика.
  4. Поставка (07-deployment.md): облако или коробка.

2. Способы передачи записей

Способ Описание
REST API системы записи мы опрашиваем список новых записей (частота — по согласованию, стандарт 1–5 мин)
Вебхуки система записи уведомляет нас о новом файле
SFTP / S3 выгрузка в каталог/бакет, забираем по расписанию
API метаданных номер, оператор, направление, кампания — если доступны

Поддерживаемые форматы аудио: wav/mp3/opus и др. (контейнер не важен), 8–48 кГц, стерео (клиент/оператор в разных каналах) или моно. Стерео-записи дают максимальную точность определения спикеров — без нейросетевой диаризации.

3. Что получает заказчик после интеграции

  • Транскрипт каждого звонка с таймкодами и метками спикера (клиент/оператор).
  • Классификацию: тип соединения (живой разговор / автоответчик / спам-блокировка / робот / без ответа), результат разговора, теги, соблюдение скрипта оператором (обязательные и запрещённые фразы), конфликтность.
  • Метрики: talk ratio, перебивания, паузы, длительность.
  • Дашборды и карточку звонка, экспорт отчётов, вебхуки и API (08-api.md).
  • Хранение транскриптов 12 месяцев (дольше — по договорённости); оригиналы остаются у заказчика.

Требования к системе описаны в 02-architecture.md; SLA и безопасность — в 07-deployment.md.

4. Анкета подключения

A. Доступ к аудио (критично)

  1. Как хранятся записи: система (АТС/биллинг/CRM — какая?), файловое хранилище, облако?
  2. Какой доступ возможен: REST API, S3/SFTP, вебхуки о новых записях, доступ к БД метаданных?
  3. Лимиты API: частота запросов, скорость отдачи, глубина выборки за запрос?
  4. Возможна ли физическая отгрузка большого архива на дисках?
  5. Кто и как быстро выдаст тестовый доступ?

B. Формат аудио (критично)

  1. Кодек и битрейт, частота дискретизации?
  2. Канальная карта: левый = клиент, правый = оператор? Всегда ли?
  3. Бывают ли моно-записи или записи с одной занятой дорожкой?
  4. Примеры «трудных» записей: автоответчики, спам-роботы, короткие сбросы, шум, IVR.

C. Объёмы (критично)

  1. Звонков в сутки: среднее и максимум; темп прироста за год?
  2. Средняя и p95 длительность звонка; общий объём архива (часы и число файлов)?
  3. Часовые пики поступления новых записей?

D. Метаданные

  1. Метаданные записи: номер звонящего, ID оператора, направление, кампания/очередь, ID в CRM?
  2. Где зафиксировано соответствие каналов и операторов по звонкам?

E. Приватность и развёртывание

  1. Где допустима обработка: контур заказчика / облако в РФ?
  2. Требуется ли маскирование номеров телефонов и иных ПДн в транскриптах и выгрузках?
  3. Сроки хранения транскриптов; требования к уничтожению по запросу субъекта ПД?
  4. Согласия на обработку записей (уведомление о записи)?

F. Отчётность и бизнес-контекст

  1. Топ-5–10 отчётов/KPI для руководства; кто получатели?
  2. Существующая BI-система (Power BI/Tableau/др.) — интеграция или наша?
  3. Как сегодня классифицируют звонки вручную? Есть ли размеченные примеры?
  4. Скрипты операторов, списки обязательных и запрещённых фраз?
  5. Какие категории «спец-ответов» операторов бизнес различает?

G. Интеграции и SLA

  1. Возвращать результаты (теги/статусы) в CRM/биллинг? В каком виде?
  2. SSO/AD для доступа к отчётам?
  3. Требования к бэкапам и времени восстановления.

Ответы на блоки A–C позволяют до пилота точно оценить объёмость (облачную или размер коробки) — без них используются консервативные оценки.
