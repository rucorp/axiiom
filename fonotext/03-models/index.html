03. Выбор моделей: распознавание речи и классификация

Версия 1.0 от 2026-10-02. Принцип: финальный выбор — только по бенчмарку на реальных данных заказчика (PoC, см. 05). Публичные метрики на «чистых» датасетах плохо переносятся на телефонное аудио, поэтому здесь даны ориентиры и критерии, а не вердикты.

1. Критерии выбора ASR

  1. Качество на телефонном русском (WER на нашей разметке) — главный критерий.
  2. Коммерчески совместимая лицензия (без NC-ограничений).
  3. Скорость (RTF) на целевом GPU при батчинге → определяет размер кластера и бюджет.
  4. Наличие word-level таймкодов (нативно или через forced alignment).
  5. Self-hosted (объём и ПДн исключают облачные API как основной путь).

Решение по диаризации

Не требуется: каналы уже разделены. WhisperX-forced-alignment используется только для word-таймкодов.

Пунктуация

Whisper выдаёт пунктуацию из коробки. Если бенчмарк выиграет модель без пунктуации (GigaAM/T-one) — добавляется модель пунктуации для русского (ruBERT-класс, ~CPU/GPU копейки) — учтено в архитектуре.

3. Классификация звонков (контекст)

3.1 Каскад «правила → LLM → человек»

Уровень 0 — аудио/дешёвые признаки (до ASR или сразу после): доля речи по каналам (VAD), длительность, бипы/DTMF, музыка, одна ли сторона говорила. Отсекает очевидные «без ответа», «тишина», короткие сбросы, часть автоответчиков — без затрат LLM.

Уровень 1 — правила по тексту: словари/regex («оставьте сообщение», «перезвоните позднее», самопредставление роботов), стоп-слова, нечёткий поиск обязательных фраз скрипта (rapidfuzz, нормализация текста). Детерминированно, объяснимо, правится бизнесом без релиза.

Уровень 2 — LLM со структурированным выводом (vLLM, JSON-schema): по транскрипту (+признаки уровня 0–1 в промпте) выдаёт строго типизированный вердикт: тип соединения, результат, флаги скрипта, конфликтность, теги, уверенность. Низкая уверенность или противоречие с правилами → уровень 3.

Уровень 3 — очередь ручного контроля: интерфейс разметки; размеченные данные идут в регресс-набор и на периодическую валидацию промптов/правил.

Оценка нагрузки LLM: ~2–4 тыс. токенов на звонок; в пике бэклога (~70 тыс. звонков/сут) — ~200 млн токейн-запросов/сутки, одна карта L40S с 14B-AWQ (vLLM, батчинг, ~2–4 тыс. ток/с) покрывает это впритык → в прод-конфигурации заложены 2 карты на LLM (см. «Поставка и внедрение»), в steady-state достаточно одной.

4. Методика оценки качества (PoC)

  1. Эталон ASR: ручная дословная транскрипция 60–90 мин аудио, стратифицированная по типам (обычные, автоответчики, шумные, короткие, «трудные»). Метрики: WER/CER общие и по слоям; сравнение моделей между собой важнее абсолютных чисел.
  2. Эталон классификации: 300–500 звонков, мультилейбл по таксономии v1 (совместно с бизнесом). Метрики: precision/recall/F1 по каждому классу; отдельно бинарная задача «живой разговор vs всё остальное» — она определяет достоверность главных KPI руководства.
  3. Скорость и ёмкость: RTF на целевой карте при реальном батчинге, включая предобработку; сколько часов аудио карта обрабатывает в сутки.
  4. Регресс-набор: зафиксированная выборка (ASR + классификация) остаётся в CI моделей — любой апгрейд модели/промптов проходит по ней перед выкаткой.

5. Вердикты, которые фиксирует PoC

  • Модель ASR для прода (ожидание: Whisper large-v3-turbo; проверить против large-v3 и, при юридической возможности, GigaAM-v2).
  • Нужна ли модель пунктуации.
  • Финальный промпт/схема классификатора и пороги уверенности.
  • Фактический RTF и пропускная способность карты → расчёт мощностей под объём заказчика.
