# SEO-аудит AXIIOM: индексация, документация и лидогенерация

**Дата аудита:** 16 октября 2026 г.  
**Область проверки:** статические файлы и конфигурация этого репозитория. Это технический аудит кода, а не проверка фактического индекса Google/Яндекса.

## Короткий вывод

Техническое задание, которое вы получили от Google AI, содержит неверную отправную точку: `/mock-services/` — **не Docsify**. В раздаваемых файлах указан VitePress 1.6.4; страницы уже сгенерированы в HTML с содержимым, заголовками и навигацией. Для каждой документационной страницы есть отдельный `index.html`, свой чистый URL и canonical. Текущий Nginx настроен отдавать `index.html` из каталога. Переключать роутер на History API, ставить Docsify SSR или добавлять общий SPA-fallback по предложенному ТЗ не требуется.

Реальные найденные проблемы были в метаданных, sitemap и обнаружении ссылок. Они исправлены в этой ветке. После генерации sitemap он содержит **139 индексируемых URL**. Все **32 страницы `/mock-services/`** остаются в sitemap и имеют серверный prerender-контент.

## Что было исправлено

1. **`mock-services` — 32 prerendered страницы**
   - Заменены автосгенерированные длинные `description`, которые часто начинались с copyright/SPDX-текста.
   - Уточнены Title для главной и ключевых интеграций: Т-Банк EACQ, Сбербанк Ecom, ЮKassa v3, АТОЛ Онлайн v4.
   - Добавлены Open Graph, Twitter Card и JSON-LD. Для главной использованы `WebSite` и `SoftwareSourceCode`: это документация открытого self-hosted ПО, а не подтверждённая SaaS-платформа.
   - Сохранены отдельные canonical URL и обычные пути без hash-mode. Title/description синхронизированы и в prerendered HTML, и в VitePress client-side bundles; им пересчитаны bundle-id, preload-ссылки и карта хэшей, чтобы клиентская навигация не возвращала старые метаданные.
   - Добавлен сквозной CTA на AXIIOM (`/#contact`) после загрузки VitePress; клики отправляют событие `mock_services_cta` в подключённую аналитику. В тексте нет неподтверждённых обещаний про сроки, бесплатность или комплаенс.
   - `mock-services/404.html` получил `noindex`; у него удалён неверный canonical на несуществующий `/404/`.

2. **Sitemap и robots**
   - Sitemap больше не включает страницы с `noindex`: удалены `/privacy/` и `/terms/`.
   - Из sitemap исключена заготовка `/demo/app/demo-template/`; сама страница помечена `noindex, follow`.
   - Генератор больше не проставляет всему сайту ложный `lastmod` равный дате каждой сборки. Sitemap сообщает только те сигналы, для которых есть надёжное значение.
   - В `robots.txt` явно разрешён публичный раздел `/mock-services/`. Он и раньше был разрешён общим `Allow: /`.
   - Не добавлялись предложенные `Disallow: */healthz`, `*/health` и запреты на `packages/core/`/скрипты: в текущей статической документации это не SEO-страницы/эндпоинты, а блокировка публичных файлов могла бы мешать обходу. `robots.txt` не является средством защиты доступа.

3. **Другие разделы**
   - В HTML блога появились статические ссылки на все 7 статей. Раньше список карточек создавался только JavaScript и был пуст в исходном HTML.
   - Сокращены слишком длинные descriptions у хаба отраслевых решений, пяти отраслевых категорий, портфолио и статьи про мобильный платёжный UX; источник генерации хаба отраслей тоже обновлён.
   - Добавлен `test_seo.py`, который проверяет sitemap, canonical, noindex, уникальность Title, метаданные mock-страниц и статические ссылки блога. Он запускается из `make test` и CI.
   - Для Docker-сборки добавлен `.dockerignore`, исключающий `.git`, `.github`, исходные Markdown/Python-файлы и внутренние каталоги документации. Nginx дополнительно запрещает отдавать скрытые файлы; это защита контейнерной сборки, а не директива для поисковика.

В sitemap нет повторяющихся URL, страниц с `noindex` и расхождений между sitemap URL и canonical для проверенных записей. Sitemap содержит индексируемые страницы, а не буквально каждый HTML-файл репозитория: 404, legal/noindex, шаблоны и внутренние материалы не должны конкурировать с коммерческими страницами.

## Что важно не копировать из исходного ТЗ

- `routerMode: 'history'` относится к другой системе маршрутизации. Здесь VitePress уже формирует URL вида `/mock-services/docs/integration/tbank-eacq/`; `#Быстрый-старт` — обычный якорь внутри страницы, а не hash-router.
- Полный текст находится в HTML до выполнения JavaScript. Дополнительный prerender-сервис или SSR не нужен.
- Запретить индексацию CSS/JS, нужных для рендеринга, нельзя: это может ухудшить проверку страницы ботом.
- Search Console не гарантирует индексацию только потому, что URL есть в sitemap. Sitemap помогает обнаружению; решение о включении в индекс принимает поисковик.
- Для JSON-LD выбрана сущность `SoftwareSourceCode`, а не `SoftwareApplication`: здесь публикуется документация к self-hosted проекту, а не веб-приложение, доступное посетителю как hosted SaaS.

## Оставшиеся вопросы и приоритеты

### P1 — проверить в Яндекс.Вебмастере и Google Search Console после деплоя

1. Отправить `https://axiiom.ru/sitemap.xml` на повторную обработку.
2. Для нескольких URL каждого типа проверить HTTP 200, canonical, доступность CSS/JS и отображённый HTML: главная, отраслевой лендинг, статья, инструмент, `/mock-services/` и T-Банк/Sбербанк/ЮKassa/АТОЛ.
3. Посмотреть отчёты «Просканирована, но не проиндексирована», «Дубликат», «Обнаружена, но не проиндексирована», выбранный Google canonical, soft-404 и ошибки рендеринга. Именно эти причины ответят, почему конкретная страница не появляется в поиске.
4. Перед продвижением `/docs/` вручную проверить, что публичные проектные документы не содержат клиентской, договорной или иной закрытой информации. Robots — не контроль доступа.

### P2 — согласовать отдельные улучшения

- Решить, следует ли индексировать `/docs/arbat38-api/` и другие страницы проектной документации, или им нужен `noindex`.
- Уточнить для 7 утилит, какая полезная инструкция/пример поможет посетителю; не добавлять пустой текст для достижения формальной длины.
- Создавать отдельные страницы портфолио только для проектов с разрешёнными к публикации, подтверждёнными деталями и результатами.
- OpenAPI JSON сейчас находится в исходном репозитории mock-services и в навигации ведёт на GitHub; файлов `openapi.json` на origin `axiiom.ru` нет. Это не блокирует индексацию HTML-документации. Если нужны JSON-схемы на собственном домене с `Content-Type: application/json`, их следует добавлять/синхронизировать как build-артефакты из исходного репозитория, а не копировать вручную.
- CTA mock-раздела сейчас добавляется клиентским скриптом после гидратации. Это помогает посетителю и аналитике; для гарантированного присутствия CTA в исходном HTML его нужно перенести в исходную тему/Markdown сайта документации. Исходников конфигурации VitePress в этом репозитории нет — здесь хранится уже собранный статический экспорт.

## Ограничения аудита

Проверены файлы репозитория и локальные правила раздачи. В этой среде не проверялись боевые HTTP-заголовки, реальный ответ Googlebot/YandexBot и данные панелей вебмастеров; локальная проверка не может подтвердить, что поисковик уже включил страницу в индекс. Для точной диагностики «почему не индексируется» нужен экспорт причин исключения URL из Google Search Console и Яндекс.Вебмастера.
