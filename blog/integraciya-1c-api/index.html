      Интеграция 1С с сайтом и банком

      1С есть почти у всех, кто работает с товарами, услугами или финансами. И почти у всех она живёт отдельно от сайта, банка и складского учёта. Разберём, как их связать и почему это обычно сложнее, чем кажется.

      Три способа интеграции

      Обмен файлами

      Самый старый и самый дешёвый способ: выгрузка из одной системы, загрузка в другую, часто по расписанию. Работает, если данные не нужны в реальном времени. Минусы — данные всегда чуть устаревшие, а при сбое нужно понять, что именно не загрузилось.

      Прямое подключение через API

      Системы общаются запросами. Данные актуальны, можно реагировать на события. Минус в том, что у 1С настройка публикации API — отдельная работа, а иногда и отдельный человек.

      Через промежуточный слой

      Между системами ставится сервис, который умеет разговаривать с каждой: забирает, преобразует, отдаёт. Это дороже, но единственный вариант, когда систем несколько или API на одной стороне неудобный. Такой слой заодно становится местом, где живут повторы, очереди и логи.

      Три ошибки, которые повторяются

      1. «Сначала сделаем, потом подумаем про сбои»

      Интеграция без обработки ошибок ломается на первом же сетевом сбое. Причём ломается тихо: заказ не дошёл, но никто не заметил. Любая интеграция должна иметь журнал, повторные попытки и алерт при сбое.

      2. Ожидание, что API само по себе документировано

      Даже если у контрагента есть документация, она часто не соответствует реальности. Практика: интеграция проверяется на реальных данных, а не на примерах из документации.

      3. Дубли заказов

      Классическая проблема: клиент обновил страницу, и заказ ушёл дважды. Решается ключами идемпотентности — механизмом, который отсекает повторную отправку того же самого.

      Ориентиры по стоимости

      Односторонняя выгрузка (например, заказы с сайта в 1С) — от 300 тысяч рублей и 2–3 недели. Двусторонний обмен с очередями, логами и мониторингом — от 500–700 тысяч и 5–8 недель. Разница в цене именно в надёжности, а не в количестве полей.

      Если API у 1С нет

      Бывает, особенно в старых конфигурациях. Тогда варианты: доработка конфигурации под публикацию API, обмен через файлы с контролем, или промежуточный слой, который забирает данные напрямую из базы по стратегии «только чтение». Последнее допустимо только на копии и требует осторожности.

      Как проверить, что интеграция жива

      • В логах видно каждый обмен, а не только ошибки
      • При сбое приходит уведомление, а не выясняется через неделю
      • Есть отчёт о расхождениях: что не дошло и почему
      • Повторная отправка того же самого не создаёт дублей

      Вопросы и ответы

      Сколько стоит интеграция с 1С?

      От 300 тысяч рублей за односторонний обмен по событию. Двусторонний с надёжностью и мониторингом — от 500–700 тысяч.

      Можно ли обойтись без программиста 1С?

      Если API опубликовано и доступно — да, интеграция делается снаружи. Если нет — потребуется доработка конфигурации.

      Что будет, если интеграция упадёт ночью?

      При нормальной настройке — повторные попытки и алерт. Данные не теряются, обмен продолжится, когда система поднимется.

      Можно ли связать несколько систем сразу?

      Да, через промежуточный слой. Это правильный выбор, когда систем больше двух — иначе получается сетка, которую невозможно поддерживать.
